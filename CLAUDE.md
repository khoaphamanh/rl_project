# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

An ablation study of PPO with two interchangeable feature extractors (MLP, GRU) on MiniGrid's partially-observable memory task (default env: `MiniGrid-MemoryS17Random-v0`; README.md's task narrative and results were written against `MiniGrid-MemoryS11-v0` — the two have drifted, don't assume README's numbers apply to the current default). The agent starts in a corridor facing away from a cue object at one end and must reach the matching object at a T-junction at the other; the cue is out of view at decision time, so a memoryless policy cannot beat chance (~0.5). `config.force_cue_visible` swaps in `StartInCueView` to pin the spawn where the cue is visible at t=0, isolating the memory half of the task from the exploration half. The GRU exists to recover performance under this state aliasing; the MLP is the memoryless control that cannot. Hyperparameters are tuned per encoder with an Optuna study (`main.py`), and there's also a "hand-picked" no-search path (`main_no_hpo.py`) for baselines/smoke tests.

A second axis, orthogonal to the encoder comparison: the GRU is tuned once per backward reach — `python main.py GRU` (full BPTT) and `python main.py GRU --tbptt L` for each L of interest — to ask whether truncating the gradient's backward reach trades a little return for materially less compute. Each length is its own **independent study in its own directory**, so no sampler or pruner ever ranks one length against another; the comparison happens between studies, after the fact. See "The tbptt ablation" below.

LSTM and Transformer encoders were removed from the project; `git log` still has them if they are ever needed again.

## Environment setup

- Python 3.11, conda env named `rl_project`. **A fresh shell here starts in conda `base`, which has no torch** — activate first (`conda activate rl_project`) or prefix commands with `conda run -n rl_project`. Every command below assumes that env.
- `requirements.txt` is the authoritative dependency list, and is Linux/macOS — on Linux PyPI's default `torch` wheel is already the CUDA build. `requirements_windows.txt` is the Windows equivalent and is **not** just a subset: PyPI's Windows `torch` wheel is CPU-only, so it pins `torch==2.11.0+cu128` against `--extra-index-url https://download.pytorch.org/whl/cu128`, and lists only what the code actually imports (no `torchvision`/`matplotlib`/`requests`; `pygame-ce` not `pygame`; `kaleido`, without which every `.svg` figure silently goes missing). The `+cu128` local version is load-bearing — without it pip may satisfy `torch==2.11.0` from PyPI and silently install the CPU build. `environment.yml` is gitignored and stale (missing `optuna`, `torchinfo`, `pandas`, `plotly`) — don't treat it as the spec.
- `optuna`/`joblib` are imported *inside* the `Helper` methods that need them, and `torchinfo`/`pandas`/`plotly` are imported lazily with a graceful skip, so a checkout missing them still trains, watches and scores — only the study, model summary, CSV export and plots drop out.

## Common commands

```bash
# Hyperparameter search (Optuna study, resumable — reruns continue an interrupted study)
# --tbptt is GRU only and fixes the backward reach for the WHOLE study; omit it for full BPTT.
python main.py MLP|GRU [--tbptt L] [--trials N] [--search-only] [--final-only]

# Hand-picked run (no Optuna), values from config/config_no_hpo.py
python main_no_hpo.py [MLP|GRU] [--tbptt L] [--report-only]

# Watch a saved checkpoint play in a pygame window
python watch.py [MODEL] [steps_per_sec] [--hpo] [--tbptt L] [--seed INDEX] [--trial best|N|final]

# Self-contained shape/forward-pass/memory/causality checks for the encoders
python models/feature_extractor.py
python models/model.py
```

There is no pytest/unittest suite and no linter or formatter configured in this repo. The closest things to tests are the `if __name__ == "__main__":` demo blocks in `models/feature_extractor.py` and `models/model.py` (both run in a few seconds and are the fastest way to check an encoder change), plus the throwaway exploration scripts under `test_enviroment/` and `no_need/` (both gitignored — not part of the shipped code, not meant to be maintained).

## Architecture

### Config layer (`config/`)

- `Config` (`config/config.py`) — abstract base holding every shared PPO/env/eval/HPO hyperparameter. Subclasses only implement `_configure_model()`. `seed_list = [0, 15, 12, 97, 98]` — every seed-averaged number in a report/study is over these five.
- `ConfigMLP` / `ConfigGRU` (`config/config_*.py`) — one per encoder; each sets `feature_extractor` and appends its own architecture knobs to the shared `search_space` (same `low`/`high`/`step` ranges for `hidden_size` in both, so the widths a study settles on are comparable). Neither puts `tbptt_length` in the search space — it is fixed per study, from the CLI.
- `ConfigNoHPO` (`config/config_no_hpo.py`) — every hyperparameter hand-picked instead of searched (`search_space = []`); used by `main_no_hpo.py`; writes checkpoints to `no_hpo/` instead of `hpo/`. Takes the encoder *and* an optional `tbptt_length` as constructor arguments (`ConfigNoHPO("GRU", tbptt_length=20)`, surfaced as `main_no_hpo.py --tbptt 20`). It does **not** set `tbptt_length` in `_configure_model()` — `Config.__init__` already took it from the flag, and reassigning it there would silently override the CLI.
- `make_config(name, tbptt_length=None)` in `config/__init__.py` turns a CLI model name into the right *tuned* `Config` subclass, forwarding `tbptt_length` (GRU only; `None` = full BPTT). It never returns `ConfigNoHPO` — that one takes the encoder as a constructor argument instead (`ConfigNoHPO("GRU")`), which is why `watch.py` branches `make_config(model, tbptt_length=args.tbptt) if args.hpo else ConfigNoHPO(model, tbptt_length=args.tbptt)`.
- `Helper` (`config/helper.py`) — large mixin `Config` inherits from; it's the rest of the project's toolbox, not more hyperparameters: env/vector-env/encoder builders, checkpoint save/load (refuses to load a checkpoint whose env/encoder/widths/`force_cue_visible` don't match the live config), `probe_batch_size`/`run_with_batch_size_fallback`, Optuna study/sampler persistence and trial-directory bookkeeping, HPO and learning-curve plotting, and the pygame `watch_agent` viewer used by `watch.py`. Also defines `Timing` (below), `StartInCueView` (an env wrapper) and `SequenceDataset` (feeds `PPOAgent`'s `DataLoader`). `build_pruner()` returns a stock `optuna.pruners.MedianPruner` wired from the `hpo_pruner_*` knobs.

### Models (`models/`)

- `feature_extractor.py` — two interchangeable encoders (`MLP`, `GRU`), both mapping `(batch, seq_len, 7, 7, 3)` MiniGrid observations to `(batch, seq_len, hidden_size)`. `flatten_obs` one-hots the observation's 3 channels into 980 features before anything else runs.
- `model.py` — `Network` wraps one encoder plus a linear actor head and a linear critic head: shared encoder, two heads, trained jointly by one optimizer.

### Agents (`agents/`)

- `ppo.py` — `PPOAgent`, the whole PPO pipeline: `sample()` (vectorized rollout collection across `n_workers` envs), `gae()`, `split_pad_mask()` (cuts each worker's `worker_steps` at episode boundaries *and* `tbptt_length` — see the tbptt ablation below — and pads to rectangles), `clip_loss()`/`minibatch_loss()` (the clipped-surrogate + value + entropy loss), `learn()`/`train()` (one iteration), `evaluate()` (sampled or argmax, on private envs), `train_agent()` (the full loop: minibatch-size probe, logging, periodic eval, timing tables, final checkpoint).
- `hpo_ppo.py` — `HPOPPO`, wraps `PPOAgent` in an Optuna study. `hpo()` runs/resumes the search: one trial draws hyperparameters and trains a fresh `PPOAgent` per seed in `config.seed_list`, pruned *between seeds* via a stock `optuna.pruners.MedianPruner` (built by `config.build_pruner()` — `hpo_ppo.py` only hands it to `create_study`). A pruning step is one **seed**: `step = seed_index`, reported in `objective()` right after `run_split()` returns, so a trial is killed between two whole training runs and never inside one — `PPOAgent` has no hook for optuna and `train_agent` cannot be stopped early. The reported value is the *running* `aggregate_scores(scores)` over the seeds finished so far, i.e. the same quantity the trial's final value is built from, over the same number of seeds for every trial at that step. Nothing is grouped any more: `tbptt_length` is fixed for a whole study, so every trial in one study is directly comparable. `plot_trial()` redraws that trial's curves right after it finishes (or is pruned), so a study that crashes or is ctrl-c'd mid-run still leaves a figure for every trial that ran, not just the winner. `final()` does **not** retrain — it reloads the winning trial's already-saved checkpoints from `best_trial/` and reports both eval modes side by side. (`main.py`'s `--final-only` help text still says "retrain"; it doesn't.)

### Entry points

- `main.py` — HPO entry point.
- `main_no_hpo.py` — hand-picked entry point; trains (or, with `--report-only`, just reports) every seed in `ConfigNoHPO.seed_list`.
- `watch.py` — loads one saved checkpoint (no training) and plays it in a pygame window. `--hpo` switches between the tuned run (`hpo/best_trial/` by default, or `--trial N`/`final`) and the hand-picked one (`no_hpo/`); `--tbptt L` (GRU only, valid with or without `--hpo`) picks the `pretrained_model_GRU_tbptt<L>/` sibling to read from; `--seed` is an **index** into `seed_list`, not a raw seed value — the same index means a different actual seed in HPO vs. hand-picked mode.

## Cross-cutting things worth knowing before touching code

- **Rollout length is the env's time limit, in both directions.** `worker_steps` (T) defaults to `Helper.env_max_steps // 4` (`env_max_steps` reads the env's own default off a throwaway `gym.make`, not hardcoded), and `build_env` then passes `max_steps=worker_steps` back into `gym.make`. So an episode can never outlive one rollout, and MiniGrid's success reward (`1 - 0.9 * step_count / max_steps`) moves with `worker_steps` — changing T silently rescales the reward and therefore every number the study compares.
- **`eval_deterministic` is one setting for an entire run**: it decides whether the learning curve, the checkpoint's stored eval, and the HPO score are *all* measured by sampling or *all* by argmax. It's read once and threaded through everywhere rather than passed per-call, specifically so switching it can't silently make two numbers incomparable. The reporting paths (`HPOPPO.score_saved`, `main_no_hpo.report_saved`) read the mode *off the checkpoint*, then measure the other mode fresh, and print the two in separate blocks — they are not comparable across.
- **Minibatch size is resolved once per run, then defended.** `mini_batch_size` in `Config` is a list of fallback candidates, largest first. `train_agent` calls `Helper.probe_batch_size` *before* iteration 0, which runs a forward/backward/step on an all-zero worst-case batch against a deepcopy of the model (early rollouts pack fewer sequences than later ones, so probing on real iteration-0 data would underestimate; the probed sequence length is `worker_steps`, or `tbptt_length` when shorter, since that's the longest chunk `split_pad_mask` can actually emit). `Helper.run_with_batch_size_fallback` then wraps each real update as a retry-on-OOM safety net. The resolved size can differ machine to machine, so it's logged and written into the checkpoint.
- **Timing is first-class** (`Timing` in `config/helper.py`). `PPOAgent` only names phases (`with self.timing.phase("sample"):`); all arithmetic/formatting lives in `Timing`. Two sets of totals are kept — `window` (since the last `report()`) and `run` (whole seed) — and `report()` folds one into the other so they never double-count. Hot inner loops pass `sync=False` because a `cuda.synchronize()` would cost more than what it measures; `evaluate()` is timed *outside* the `"iteration"` clock, since it's the cost of measuring the policy, not of training it. Adding a phase means adding a key to `Timing.ROWS`/`ROWS_EVAL` — an untimed-but-unlisted phase accumulates silently and just isn't printed.
- **`hpo_objective` accepts exactly two strings**: `"return_mean_minus-std"` or `"success_rate_mean_minus-std"`, parsed by `helper.parse_hpo_objective`/`_HPO_OBJECTIVES`, which raises on anything else rather than defaulting silently. Both are scored `mean - hpo_lambda * std`, **across seeds**, never across eval episodes within one run — the within-run spread of a bimodal return is a function of the success rate itself and would penalize partial success. (`return_std_episodes` in reports is the within-run one; `std_across_seeds` is the scored one.) `Helper.aggregate_scores` computes that number and is the only thing a trial is ranked on.

- **The pruner compares "my best ever" against "your right now."** Optuna's `MedianPruner` prunes when `max(this trial's intermediate values, over ALL steps)` falls below `median(other COMPLETE trials' value at THIS step)` — the two sides are not the same statistic, and the asymmetry deliberately biases it against pruning. With one step per seed a trial only ever has `len(seed_list)` values, so that safety margin is thin: there is no long tail of later checks to correct an early call, and `hpo_pruner_warmup` (in **seeds**, default 0 → first check after seed 0) is the only real defence. Pruning on seed 0 alone is a genuinely aggressive bet that one seed predicts five, and the 50-trial GRU study in `no_need/log_2026-08-06_22-46-09.log` shows what it costs: all 25 of its prunes fired after seed 0, four of them on draws whose seed-0 `return_mean` was 0.937–0.956 — level with the eventual winner's per-seed values. Setting the warmup to 1 judges on two seeds instead of one, at roughly half the savings. Note also that the value reported is the *running* aggregate, so from seed 1 on it already carries a cross-seed std penalty: a trial with one bad seed out of two is judged on `mean - std` of those two, which is far below either.
- **A tuned checkpoint carries its own architecture.** `save_model` writes `searched_params()` into the file, so reloading a trial drawn at `hidden_size=384` means `config.apply_params(config.checkpoint_params(path))` *before* building `PPOAgent` — the agent reads sizes into the model at construction and never consults the config again. Every reload path does this; a new one must too. `apply_params` raises on a name that isn't already an attribute of the config, so a new `search_space` entry requires the attribute to exist on the config first.
- **Checkpoint layout**: `agents/pretrained_model_<ENCODER>[_tbptt<L>]/`, split into `hpo/trial_<n>/`, `hpo/best_trial/` (the winner, copied out so `trial_*/` can be deleted), and `no_hpo/` (hand-picked runs). The `_tbptt<L>` suffix is set by `Config.__init__` from the constructor's `tbptt_length` and applies to **both** `hpo/` and `no_hpo/`, so full BPTT keeps the plain `pretrained_model_GRU/` it always had and each truncated length gets a complete sibling tree (`pretrained_model_GRU_tbptt8/hpo/`, `pretrained_model_GRU_tbptt8/no_hpo/`). An MLP with a `tbptt_length` raises rather than silently making a directory that means nothing. `config.select_run()` is the single place that resolves a seed index to a checkpoint path within whichever of those a config was built to point at; `HPOPPO`, `main_no_hpo.py`, and `watch.py` all go through it so they can't drift apart. Each `.pth` also carries its `eval_history`, which is what `plot_eval_curves` redraws from — a directory of checkpoints is a set of curves (one mean±std `.html`/`.svg` pair per metric in `_HPO_METRICS`, i.e. `return_mean` and `success_rate`; the older median/IQR figure was dropped).
- **No dropout, anywhere.** PPO compares rollout `log_probs` against `log_probs` recomputed during the update; dropout makes those differ on identical inputs for reasons unrelated to learning, corrupting the ratio. Neither encoder has any, and none should be added.
- **`async_envs`** picks `AsyncVectorEnv` (separate processes, the default) vs `SyncVectorEnv`. Async must be `False` in notebooks and any script without an `__main__` guard — macOS spawns subprocesses.
- **The tbptt ablation** truncates only the *backward* pass, not the forward one. `config.tbptt_length` ("max", or an int) is read by `PPOAgent.split_pad_mask`, which cuts each worker's stream at episode boundaries **and** every `tbptt_length` steps, instead of episode boundaries only. A chunk that starts mid-episode is seeded from the hidden state `sample()` recorded at that timestep (`buf["hxs"]`), so the encoder still sees the full history going forward — only how far the gradient is allowed to flow back through time shrinks. It is **never searched**: each length is a separate `main.py GRU --tbptt L` study in its own directory, deliberately, so that neither the TPE sampler nor the pruner ever ranks one length against another. (Optuna's TPE reads PRUNED trials and ranks all of them below every COMPLETE one, so a pruner working inside a single mixed-length study would have driven the sampler off short lengths and answered the ablation itself.) The lengths are compared afterwards, by reading the three studies' `final_*.json`. There is no `tbptt_lambda` penalty any more — with lengths in separate studies there is nothing to trade off inside a score. Note that shorter is not automatically cheaper: `L=1` measured *slower* than full BPTT, because `split_pad_mask` then emits `W*T` sequences of length 1 and the update runs many more minibatches; `L=8` was the fastest of the lengths tried.
- `logs/` holds one timestamped log file per command invocation (`build_logger`), mirroring everything printed to the terminal, with every hyperparameter dumped at the top.
